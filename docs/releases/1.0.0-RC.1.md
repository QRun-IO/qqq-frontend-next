# Next UI 1.0.0-RC.1 — release preparation

**Status: not published.** This candidate is being prepared for testing in real QQQ applications. The final 1.0 visual review and compatibility work remain open. Local Chromium acceptance is complete; CI and verification of the distributed artifacts remain before publication; the checks below are local evidence, not a release announcement.

## Install once published

Use the Maven artifact in your application, overriding any older BOM-managed dashboard version:

```xml
<dependency>
    <groupId>com.kingsrook.qqq</groupId>
    <artifactId>qqq-frontend-next</artifactId>
    <version>1.0.0-RC.1</version>
</dependency>
```

Select Next with `-Dqqq.javalin.frontend=next`. `QApplicationJavalinServer` serves the dashboard at `/` alongside `/qqq/v1`; no Node server is needed for this distribution. Keep the Material dependency available during evaluation if you need to switch back with `-Dqqq.javalin.frontend=material`. Their deep-link formats differ; use `/app/{table}/{id}` in Next.

The candidate is tested against the QQQ **4.1.0-SNAPSHOT development backend**, including the current v1 endpoint, session, metadata and process fixes. This does not publish QQQ 4.1 or establish compatibility with every older QQQ release. Pin the backend version/commit used by the application and include it in bug reports. The Sleep Interactive sample fix was merged to QQQ `develop` as `e33e1fc52c55c203e3ee3014837970ef2614b809` in [QQQ PR #896](https://github.com/QRun-IO/qqq/pull/896).

The planned container tag is `ghcr.io/qrun-io/qqq-frontend-next:1.0.0-RC.1`. Its backend origin is fixed at image build time; the provided quickstart image expects `http://host.docker.internal:8000`. For other deployments, use the Maven artifact or build the container with the appropriate backend configuration. Publication and image digest verification are still pending.

## Testing priority and evidence

For RC1, complete workflows in **Chromium** take priority over additional browser and viewport combinations. Test normal entry and defaults, validation, editing/cancellation, save/reopen, dependent selections, permissions, recovery and actual persisted data or downloaded files. A passing scenario count does not prove every application configuration works.

## Known gaps before final 1.0

The [Material behavior parity ledger](../acceptance/material-parity.md) remains authoritative. Its current summary has 795 entries: 728 Done, 22 Done with different UX, 5 Partial, 2 Missing and 38 N/A. The cross-cutting overlay section repeats entries and is not added to those totals.

- Hosting under a URL base path is not implemented ([#732](https://github.com/QRun-IO/qqq/issues/732)). Evaluate at the origin root.
- Google Drive folder selection remains a stub ([#704](https://github.com/QRun-IO/qqq/issues/704)).
- Full embedded report/query equivalence review remains ([#722](https://github.com/QRun-IO/qqq/issues/722)).
- Remaining input-block configurations and unsupported Material icon names need completion ([#728](https://github.com/QRun-IO/qqq/issues/728)).
- Script editor autocomplete is absent ([#724](https://github.com/QRun-IO/qqq/issues/724)).
- Full visual comparison against the original Next UI design remains open. Behavioral parity with Material does not change that visual reference.

These are recorded gaps, not exclusions approved for final 1.0. Application-specific external providers also need testing with the application's own configuration.

## Report an issue

Open a [Next UI issue](https://github.com/QRun-IO/qqq-frontend-next/issues/new) with the dashboard version, QQQ backend version/commit, browser, affected widget or metadata configuration, steps from a fresh page, expected and actual results, and whether it survives reload. Include a screenshot or sanitized console/network error where useful. For reports, include selected table, filters, sorts and columns; for processes, include the step and relevant input configuration. Remove credentials, session cookies and private application data.

See the [developer guide](../guides/next-ui-developer-guide.md), [agent guide](../guides/next-ui-agent-guide.md), and [acceptance instructions](../../tests/acceptance/README.md).
