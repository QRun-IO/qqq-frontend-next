# Next UI 1.0.0-RC.3 — candidate preparation

**Not yet published.** This candidate fixes multiline field behavior discovered during deeper workflow testing. Final 1.0 remains on hold for owner testing and explicit approval. RC1 and RC2 remain immutable.

## Changes since RC2

- Multiline `TEXT` fields now honor backend `TO_UPPER_CASE` and `TO_LOWER_CASE` behaviors while typing. The shared field editor preserves the caret and newlines, and submits the displayed transformed value. Existing textarea layout and styling are unchanged.
- Added regression coverage for case conversion in standalone blocks and process fields, including edits in the middle of a value, multiline Enter without submission, and exact values persisted to the backend. Single-line ASCII conversion already worked in RC2; its new tests document and verify that behavior.
- Corrected the shared caret mapping for Unicode case expansion in both `STRING` and `TEXT` fields (for example, `ß` to `SS`). Continued typing stays after the inserted text, and backward selections retain their direction.
- Developer and agent guides explain the field behavior and keyboard differences. RC2 release and browser documentation now records its published artifacts and completed tag validation.
