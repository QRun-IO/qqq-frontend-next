# Next UI 1.0.0-RC.37 — published collaboration candidate

This candidate is published. Artifacts are
`com.kingsrook.qqq:qqq-frontend-next:1.0.0-RC.37` and
`ghcr.io/qrun-io/qqq-frontend-next:1.0.0-RC.37`. RC.36 remains immutable.
Publication does not deploy Kof22 or authorize final 1.0.

## Source and changes

Prepared from collaboration source `dce92cfba1f02f7969c19b59d4442f5488b3821e`.
The RC preparation changes the package and Maven versions together and retains
main's managed orb 0.8 publication configuration. This source
includes the previously tested collaboration source
`8d372142f8af0c41a75a353edc6d150c33ccf613` plus a My Work browser regression test.

- Presence opens server-issued leases and renews them through
  `/presence/leases` and `/presence/leases/renew`. Record/table viewers and
  editors receive updates through the existing SSE/HTTP transport.
- Authentication retains the Auth0 display profile while using canonical
  backend presence identity. Departure, expired leases and reconnect behavior
  remain covered by the collaboration test suite.
- Marking a mention read refreshes My Work; the additional browser test checks
  that behavior.
- Changes since RC.36 also include assistant conversation navigation, unread
  state and attachment recovery, startup branding, shared HTML sanitization,
  dependency fixes and centralized CI. This is not a presence-only diff from
  RC.36.
- Development dependencies are aligned on Storybook 10.6.2 and Vitest 4.1.12
  (including `@vitest/mocker`) for
  [GHSA-f2ph-cmg5-wxc8](https://github.com/storybookjs/storybook/security/advisories/GHSA-f2ph-cmg5-wxc8)
  and [GHSA-xp26-3454-mjgp](https://github.com/vitest-dev/vitest/security/advisories/GHSA-xp26-3454-mjgp).
  These advisories affect development-server tooling; they do not describe a
  Storybook server in the static dashboard package. Integration is tracked in
  [QQQ #1327](https://github.com/QRun-IO/qqq/issues/1327).

## Backend pairing

Use a backend implementing the issued-lease collaboration API. The verified
earlier pair is QQQ `4.1.0-collab-33464d37e-SNAPSHOT` with collaboration
`0.1.0-collab-8f348da-SNAPSHOT` and Redis `0.1.0-redis-7fe5492-SNAPSHOT`.
The selectable-field follow-up pair is QQQ
`4.1.0-virtual-field-values-1196-cc3981bb3-SNAPSHOT` with collaboration
`0.1.0-field-values-1196-ecff347-SNAPSHOT`; that pair's independent API probe
does not establish packaged frontend acceptance.

Configure authenticated scope, Redis namespaces and lifecycle, SSE delivery and
connection affinity in the host. Presence is advisory; stale-save protection
still requires backend record versions. Kof22 PR338's RC.36 frontend must be
updated only after this artifact is published and independently verified.

## Limits and rollback

This branch does not include separate frontend PR194/195 or the independent
backend attachment, My Work and Redis-recovery follow-ups. Those remain tracked
in the QQQ project.

If packaged acceptance fails, withhold adoption and fix the candidate. After
deployment, restore a previously qualified frontend/backend pair together;
RC.36 must not be substituted against a backend requiring issued leases.
No host data migration, production deployment or GA approval is implied.
